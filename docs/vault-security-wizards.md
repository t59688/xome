# Xome / 独立空间与密码修改的分步向导

## 设计目标

原设置页在一张卡片中并列放入名称、两个密钥输入框、示例文件选项和创建动作，另一个卡片并列放入旧/新/确认序列。窄屏中表单密度高，用户无法知道目前正在解决哪件事；“生成示例文件”还曾错误地控制了空间访客标记，真实加密存储总是生成示例文件。

**方向：一次只做一个决策。** 沿用 Xome 的曜石/暖铜/淡紫视觉变量，不新增无关装饰。入口保留在“私密空间 → 设置”中，但仅显示两条简洁的设置项；点击后才打开全屏专注向导。所有按钮和输入都是 Compose Material3 控件，语言跟随现有设置。

## 操作流程

**新建独立空间：** 名称（含访客/工作/临时快捷名称）→ 自有解锁序列（4–16 字符，支持计算表达式 + 再次确认）→ 空间选项（访客模式、是否生成示例文件、是否立刻进入，三个独立开关）→ 查看摘要并创建 → 成功结果。创建成功后不在提示、日志或通知中展示完整解锁序列。

**修改解锁密码：** 输入并验证当前序列 → 新序列及确认（不得与旧序列相同）→ 修改摘要 → 更新包装 Master Key 的头文件 → 成功结果。解锁校验走独立轻量后台验证，不新开空间会话；最终提交仍由原有加密逻辑重新认证旧序列。原 .db/.dat 加密数据不被重新加密。

## 交互与状态

- 顶部步骤指示器有当前/已完成状态；仅当前步骤的内容处于主视觉焦点。
- 固定底部主操作区；页面正文可垂直滚动，布局考虑 Android 状态栏、导航栏和 IME Insets。
- 主按钮基于名称有效性、序列长度、确认匹配及等待状态控制，不允许双次提交；后台处理中按钮替换为进度环。
- 返回上一步保留**当前内存中的**输入，关闭向导即销毁输入；密码值只存于 `remember` 而不是 `rememberSaveable`，不会在重新创建 Activity 时复原明文。
- 显示/隐藏密码是显式可访问控件；错误就地显示，且不暴露加密密钥或旧序列。
- 原空间安全锁定、文件导入、导出备份、语言设置、应用更新入口没有改动。
- 无新网络依赖，无第三方 UI 组件。

## 验证

- Kotlin 编译与 `:app:testDebugUnitTest`；`VaultWizardRulesTest` 覆盖名称、表达式格式、确认匹配、禁止无变化改密。
- `VaultSecurityWizardUiTest` 使用 Robolectric+Compose 验证引导式步骤、无法越过无效序列确认、当前序列验证失败/成功及最终回调、复用的 Switch 控件。
- 使用隔离测试包 `com.aizeek.xome.wizardqa` 和隔离存储 `.sys_vault_data_wizardqa` 在 1080×2400 Android 模拟器验证新空间名称预设和跳转、改密端到端成功；模拟器原有 `.sys_vault_data` 不修改。截图作为过程证据留在忽略目录 `build/`，不应作为公开仓库素材。
- 向导没有调用系统原生 Alert/系统选择器；不修改存储加密格式。
